[FOUNDATIONAL — Easy]
--------------------------------------
 01. Composition (Has-A Relationship)     -> 01_Composition.py
     A class CONTAINS another class as an attribute instead of inheriting from it.
     Real-life: A Car HAS-A Engine. A Person HAS-A Address.
     "Favor composition over inheritance" is a famous design principle.

 02. Aggregation                          -> 02_Aggregation.py
     A WEAKER form of composition. The contained object can exist independently.
     Real-life: A Department HAS Teachers, but Teachers exist without the Department.
     Key diff from Composition: In composition, the child dies with the parent.
                                In aggregation, the child survives independently.

 03. Method Overloading (Simulated)       -> 03_Method_Overloading.py
     Python doesn't have true method overloading like Java/C++.
     We simulate it using: default arguments, *args, or @singledispatchmethod.
     Real-life: A "draw" function that draws either a circle, square, or triangle.

 04. Operator Overloading (Complete)      -> 04_Operator_Overloading_Complete.py
     You covered __add__, __lt__, __gt__ already. This adds:
     __sub__, __mul__, __truediv__, __contains__, __getitem__, __setitem__
     Real-life: A Vector class where v1 + v2, v1 * 3, v1[0] all work naturally.

[INTERMEDIATE]
--------------------------------------
 05. Dataclasses (@dataclass)             -> 05_Dataclasses.py
     Python 3.7+ feature. Auto-generates __init__, __repr__, __eq__ etc.
     Reduces massive boilerplate code. Used widely in modern Python projects.
     Real-life: A Product class with name, price, stock — no manual __init__ needed.

 06. __slots__                            -> 06_Slots.py
     Restricts which attributes an object can have.
     Saves memory and speeds up attribute access.
     Prevents accidental creation of new attributes.
     Real-life: High-performance Point(x, y) class for game engines.

 07. Class Variables vs Instance Variables -> 07_Class_vs_Instance_Variables.py
     Deep dive into: shared class-level data vs per-instance data.
     Covers the famous MUTABLE DEFAULT TRAP with lists/dicts as defaults.
     Real-life: Employee class with shared company_name (class) and unique salary (instance).

 08. Mixins                               -> 08_Mixins.py
     Small reusable classes that add specific behavior (mixed-in).
     They are NOT standalone — they're meant to be combined with other classes.
     Real-life: LoggingMixin, SerializationMixin, ValidationMixin.

 09. Abstract Properties                  -> 09_Abstract_Properties.py
     Combining @abstractmethod with @property.
     Forces subclasses to implement properties, not just methods.
     Real-life: Shape class forces all subclasses to have an "area" property.

 10. Enum Classes                         -> 10_Enum_Classes.py
     Using enum.Enum to create named constants with OOP power.
     Prevents magic numbers in code. Type-safe. Iterable.
     Real-life: Color.RED, Status.ACTIVE, Direction.NORTH.

 11. Context Managers (__enter__/__exit__) -> 11_Context_Managers.py
     Makes objects usable with the "with" statement.
     Guarantees cleanup (even if errors occur).
     Real-life: Database connections, file handling, timer utilities, locks.

 12. Iterators & Iterables (__iter__/__next__) -> 12_Iterators_and_Iterables.py
     Making your custom objects work with "for" loops.
     Implementing the iterator protocol from scratch.
     Real-life: A NumberRange(1, 10) object you can loop through.

[ADVANCED]
--------------------------------------
 13. Metaclasses                          -> 13_Metaclasses.py
     Classes that CREATE other classes. The class of a class.
     type() is the default metaclass. You can make custom ones.
     Controls class creation itself — add methods, validate structure, etc.
     Real-life: Django ORM uses metaclasses to auto-create database models.

 14. Descriptors (__get__/__set__/__delete__) -> 14_Descriptors.py
     The mechanism BEHIND @property, @classmethod, @staticmethod.
     Understand how attribute access truly works in Python.
     Real-life: A Validated descriptor that only allows positive numbers.

 15. __new__ vs __init__                  -> 15_New_vs_Init.py
     __new__ CREATES the object (allocates memory).
     __init__ INITIALIZES the already-created object.
     Essential for: Singleton pattern, immutable types like int/str, metaclasses.

 16. Multiple Dispatch (@singledispatchmethod) -> 16_Multiple_Dispatch.py
     True method overloading based on argument TYPE at runtime.
     Uses functools.singledispatch and singledispatchmethod.
     Real-life: A Formatter that handles int, str, list differently.

[OOP DESIGN PATTERNS]
--------------------------------------
 17. Singleton Pattern                    -> 17_Singleton_Pattern.py
     Ensures a class has ONLY ONE instance throughout the program.
     When you need it: Database connections, config managers, logging.
     Implementation: Using __new__, using module, using metaclass.

 18. Factory Pattern                      -> 18_Factory_Pattern.py
     Creates objects without specifying the exact class to create.
     The factory decides WHICH subclass to instantiate based on input.
     Real-life: A NotificationFactory that creates Email, SMS, or Push notifications.

 19. Observer Pattern                     -> 19_Observer_Pattern.py
     Objects (observers) SUBSCRIBE to events from a subject.
     When subject changes, ALL observers are automatically notified.
     Real-life: YouTube channel subscriptions, event listeners in UI frameworks.

 20. Strategy Pattern                     -> 20_Strategy_Pattern.py
     Defines a family of INTERCHANGEABLE algorithms/behaviors.
     Client can SWAP strategies at runtime without changing code.
     Real-life: Payment methods (CreditCard, PayPal, Crypto) in an e-commerce app.
